# 产出物交付门禁（Artifact Gates）

> 命中场景：生成 HTML 报告 / 大文件产出 / 写 shell·python 脚本 / 报告里带数字结论时。
> 与 `rules/verification.md` 的分工：那条管「改配置后要 read-back + restart」，本条管「**产出物**交付前必须过的自动门禁」。

## Iron Law: 产出物没过 gate 不算完成

写完 ≠ 能看 ≠ 正确。每类产出物有各自的最小 gate，**gate 未过不得声明完成**。

## Gate 1 — 大文件落盘验证

`verify-on-stop.sh`（PostToolUse hook）已自动兜底：文件 >10KB 时注入磁盘实测字节数/行数，size=0 时告警。

模型侧配合：
- 向 Tony 报告大产出时，**引用 hook 给的磁盘实测数字**，不要报"已写入"了事
- 数字与预期明显不符（截断 / 半写）→ 下一轮 Read 复核再声明完成
- 没看到 hook 回执（比如通过 Bash 重定向写的文件）→ 自己 `wc -c` 补一次

## Gate 2 — HTML 产出必须验证渲染

历史事故：图表绑定滚动触发动画 → 首屏截图全空白；UTF-8 字节截断 → 整页乱码；写入回执成功但文件根本没落盘。**这些都是截图一次就能发现的**。

HTML 交付前逐项过：
1. **渲染验证**：用 `/browse` 或 Playwright headless 打开，截**整页**（不只首屏）
2. **图表非空**：滚到底部再截一次——只在首屏截图会漏掉滚动触发的图表
3. **占位符扫描**：页面不得残留 `undefined` / `NaN` / `null` / `TODO` / `XXX` 字样
4. **中文渲染**：CJK 不得出现乱码方块（UTF-8 截断的典型表现）

飞书场景的 HTML→PDF 另有专门流水线，见 `rules/feishu-bot.md`。
本地深度页走想法工坊，见 `rules/ideaforge.md`（写 HTML 已由 hook 自动归档，但**归档不等于验证过**）。

## Gate 3 — 数字必须可溯源

报告 / 分析里出现的每个数字，必须能指到来源（源文件、抓取记录、命令输出）。

- 拿不到真实数据时**如实说拿不到**，绝不用"看起来合理"的数字填空
- 覆盖率不足就写明覆盖率（历史正解：报告标注"89% 覆盖"而不是假称 100%）
- Tony 已经明说要"可溯源"的场景，在产出里直接标注每个数字的来源

## Gate 4 — 脚本静态检查

`script-lint.sh`（PostToolUse hook）已自动检查：`.sh` 走 `bash -n` + shellcheck(-S info)，`.py` 走 ruff + stdlib 同名冲突。

**hook 报 ❌ 的必须修掉再运行脚本**。另外这些坑 hook 不一定抓得到，写的时候自己避开：

- `printf "$var"` — 变量进格式串 = 格式注入，中文/百分号会炸；一律 `printf '%s' "$var"`
- 管道里的 `while read` 跑在 subshell，循环内对外部变量的修改**全部丢失**；改用 here-string `done <<< "$x"`
- `set -u` 下未定义变量直接终止脚本；可能不存在的一律 `${VAR:-}`
- 文件名别撞 Python 标准库（`html.py` / `json.py` / `time.py`…），`import` 会静默拿到你的文件
- 中文文本做 regex / 截断前，先拿**真实中文样本**测；按字节截断必出 UTF-8 乱码

## Gate 5 — 批量作业先跑样本

批量提取 / 生成 / 转换：**先用 3-5 个真实样本验证逻辑**，确认无误再跑全量。

- 多阶段流水线：每阶段输出验完再进下一阶段，别一口气跑到底才发现第一步就错
- 子串匹配是重灾区（历史：`自动化` 把 `电气工程及其自动化` 一并吞掉）——用精确匹配或加边界
- 全量跑之前把进度落盘 ledger，撞中断能续跑
