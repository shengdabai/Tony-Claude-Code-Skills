# Coding Style

**写代码按下面五条本机偏好来;通用写法交给模型判断力,不在本文件重复业界常识。**

**Why**:能被 linter / formatter / type checker 机械抓到的东西写进规则文件是纯浪费——它们每次都进 context,却永远不如工具准。这里只留工具抓不到、且 Tony 有明确偏好的判断题。

- **不可变优先**:返回新对象,不 mutate 入参。
- **小文件高内聚**:200-400 行典型,800 行上限;按 feature/domain 组织,不按 type。
- **错误与校验**:外部输入必校验(zod 优先);catch 带上下文重新抛出,不静默吞错。
- **完成自查**:无硬编码值、无 >4 层嵌套、函数 <50 行。(调试残留 `console.log`/`print` 交给 eslint `no-console` 与 ruff `T20`,不在这里重复。)
- **新功能先找轮子**:实现较大新功能前先搜 battle-tested 骨架项目/现成模式,评估后在成熟结构内迭代,不从零造。
